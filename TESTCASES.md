# Тест-кейсы UI — задание 2.2

## Область тестирования

Объект тестирования — платформа модерации объявлений:

- главная страница со списком объявлений — `/`, `/list`;
- страница статистики — `/stats`;
- мобильная версия главной страницы.

Тест-кейсы покрывают все пользовательские сценарии, перечисленные в задании 2.2. Проверки рассчитаны на общий изменяемый стенд: они не зависят от фиксированного количества объявлений, их идентификаторов, названий или заранее известного состояния данных.

## Общие условия

| Параметр | Значение |
|---|---|
| Стенд | `https://cerulean-praline-8e5aa6.netlify.app` |
| Desktop | Chromium, viewport не меньше 1280×720 |
| Mobile | Chromium, viewport 390×844 |
| Начальное состояние | Страница открывается без авторизации; данные объявлений успешно загружены |
| Критерий прохождения | Фактический результат каждого шага соответствует ожидаемому |

Перед каждым кейсом используется новая страница браузера. Если в выдаче нет данных, необходимых для проверки, это считается проблемой тестового окружения, а не успешным результатом функционального теста.

## UI-01 — фильтрация по диапазону цен

| Поле | Значение |
|---|---|
| Раздел | Главная страница |
| Приоритет | P1 — высокий |
| Тип | Функциональный, позитивный, граничные значения |
| Предусловия | Открыта desktop-версия; отображается не менее одной карточки с ценой |
| Тестовые данные | Нижняя и верхняя границы формируются по ценам текущей выдачи, чтобы тест не зависел от изменяемых данных |

| № | Действие | Ожидаемый результат |
|---:|---|---|
| 1 | Зафиксировать цены карточек текущей страницы и определить нижнюю и верхнюю границы. | Получены числовые значения; нижняя граница не превышает верхнюю. |
| 2 | Ввести границы в поля «Диапазон цен». | В полях отображаются введённые значения. |
| 3 | Применить фильтр. | Выдача обновлена; страница остаётся работоспособной. |
| 4 | Получить цены всех показанных карточек. | Выдача не пуста. Каждая цена удовлетворяет условию `нижняя граница ≤ цена ≤ верхняя граница`; значения на самих границах допускаются. |

## UI-04 — фильтрация по категории

| Поле | Значение |
|---|---|
| Раздел | Главная страница |
| Приоритет | P1 — высокий |
| Тип | Функциональный, позитивный |
| Предусловия | Открыта desktop-версия; отображается минимум одна карточка |
| Тестовые данные | Категория берётся из реально показанной карточки и должна присутствовать в списке фильтра |

| № | Действие | Ожидаемый результат |
|---:|---|---|
| 1 | Зафиксировать категорию первой карточки. | Получено непустое название категории. |
| 2 | Раскрыть фильтр «Категория». | В списке присутствует зафиксированная категория. |
| 3 | Выбрать эту категорию. | Фильтр отображает выбранное значение; выдача обновлена. |
| 4 | Проверить категорию каждой показанной карточки. | Выдача не пуста. Все карточки относятся только к выбранной категории. |

## UI-06 — ручное обновление статистики

| Поле | Значение |
|---|---|
| Раздел | Статистика |
| Приоритет | P1 — высокий |
| Тип | Функциональный, позитивный |
| Предусловия | Страница `/stats` открыта через навигацию приложения; контейнер таймера отображается |

| № | Действие | Ожидаемый результат |
|---:|---|---|
| 1 | Дождаться, пока обратный отсчёт станет меньше полного интервала. | Отображается корректное значение таймера в формате `M:SS`. |
| 2 | Нажать «Обновить». | Выполняется успешный запрос обновления данных; интерфейс не показывает ошибку. |
| 3 | Проверить состояние контейнера. | Данные статистики обработаны, а обратный отсчёт сброшен к полному интервалу `5:00`. |
