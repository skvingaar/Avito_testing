# Тест-кейсы UI

Стенд: `https://cerulean-praline-8e5aa6.netlify.app`  
Область проверки: пользовательские сценарии задания 2.2 и дополнительные граничные сценарии.  
Окружение: актуальные Chromium и Firefox; desktop viewport не меньше 1280×720, mobile viewport 390×844.

> Тестовые данные выбираются из текущей выдачи. Кейсы не зависят от фиксированного количества объявлений, заранее выбранных ID и неизменности данных общего стенда.

## UI-01 — фильтрация по валидному диапазону цен

**Priority:** P1

## Preconditions
- открыта desktop-версия главной страницы
- отображаются карточки минимум с двумя различными ценами

## Test Data
- Границы выбираются по ценам текущей выдачи так, чтобы внутри диапазона было хотя бы одно объявление

## Steps | Expected Result
1. Определить нижнюю и верхнюю границы по текущей выдаче. | Получены числовые значения, `min < max`.
2. Ввести границы и применить фильтр. | Выдача обновлена; введённые значения сохранены без изменения.
3. Проверить цены всех показанных карточек. | Выдача не пуста; каждая цена удовлетворяет условию `min ≤ цена ≤ max`.

# Результаты повторной проверки

Дата проверки: 28.08.2026.

## Автоматизированные кейсы

- Chromium: `7 passed, 2 xfailed`.
- Firefox: `7 passed, 2 xfailed`.
- UI-11: ожидаемо `XFAILED`, известный `BUG-01` — обычные карточки остаются после включения «Только срочные».
- UI-17: ожидаемо `XFAILED`, известный `BUG-02` — запуск после остановки не возобновляет таймер.
- UI-15: PASSED в Chromium и Firefox. После нажатия «Обновить» данные успешно запрашиваются, а таймер сбрасывается. Различие в способе загрузки данных между браузерами не влияет на результат.

## Дополнительные РУЧНЫЕ проверки в Chromium и Firefox

- UI-02: **PASSED** — показано корректное пустое состояние. Дополнительно замечено смещение обеих ценовых границ в URL на `+5000`.
- UI-03: **FAILED** — после ввода `0–0` в URL передаётся `5000–5000`.
- UI-04: **FAILED** — для реально существующей цены получена пустая выдача; границы в URL увеличены на `5000`.
- UI-05: **FAILED** — корректно вычисленный диапазон с одной карточкой даёт пустую выдачу из-за смещения границ на `+5000`.
- UI-08: **PASSED** — две карточки с одинаковой ценой не нарушают сортировку; их порядок совпал в трёх повторах и обоих браузерах.
- UI-10: **FAILED** — «Сбросить фильтры» не снимает категорию и не удаляет `categoryId` из URL.
- UI-12: **FAILED** — на средней странице присутствует обычная карточка.
- UI-13: **FAILED** — на последней странице присутствуют обычные карточки.
- UI-14: **FAILED** — категория применяется, но срочный фильтр пропускает обычные карточки; ценовые параметры смещаются на `+5000`.
- UI-18: **FAILED** — обновление `/stats` открывает страницу Netlify `Page not found`.
- UI-20: **OBSERVED** — изменение системной схемы `light → dark` не меняет тему сайта. Без требования о поддержке системной темы это наблюдение, а не подтверждённый дефект.
