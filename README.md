# UI-тесты платформы модерации

Автоматизация задания 2.2 выполнена на Python, pytest и Playwright. Покрыты фильтры цены и категории, сортировка цены в обоих направлениях, «Только срочные», управление таймером статистики и мобильное переключение темы.

Решение обязательного задания 1 по скриншоту находится в `SCREENSHOT_BUGS.md`, тест-кейсы UI — в `TESTCASES.md`, найденные на стенде дефекты — в `BUGS.md`.

## Что нужно для запуска

- компьютер с Windows, macOS или Linux;
- Python версии 3.10 или новее;
- доступ в интернет: при первом запуске скачиваются библиотеки и Chromium, а сами тесты открывают опубликованный стенд.

Проверить наличие Python можно командой `python3 --version` на macOS/Linux или `py --version` на Windows. Если Python не установлен, его можно скачать с [python.org](https://www.python.org/downloads/). На Windows при установке следует включить пункт **Add Python to PATH**.

## Самый простой запуск

Скопируйте всю папку проекта на другой компьютер. Не нужно копировать скрытую папку `.venv`: она создаётся отдельно на каждом устройстве.

### macOS

1. Откройте Finder и найдите папку проекта.
2. Нажмите папку правой кнопкой и выберите **Службы → Новый терминал в папке**. Если такого пункта нет, откройте приложение «Терминал», введите `cd ` с пробелом, перетащите папку проекта в окно и нажмите Enter.
3. Выполните:

```bash
python3 run_tests.py
```

### Windows

1. Откройте папку проекта в Проводнике.
2. Щёлкните по адресной строке, введите `powershell` и нажмите Enter.
3. Выполните:

```powershell
py run_tests.py
```

### Linux

Откройте терминал в папке проекта и выполните:

```bash
python3 run_tests.py
```

При первом запуске скрипт сам создаст `.venv`, установит зависимости и Chromium. Это может занять несколько минут. Затем откроется браузер и начнётся проверка сайта. При следующих запусках подготовка повторяться не будет.

## Варианты запуска

Без видимого окна браузера:

```bash
python3 run_tests.py --headless
```

Только desktop- или только mobile-сценарии:

```bash
python3 run_tests.py --desktop
python3 run_tests.py --mobile
```

На Windows в этих командах замените `python3` на `py`.

Если зависимости или Chromium нужно установить заново:

```bash
python3 run_tests.py --setup
```

Любые дополнительные параметры pytest можно дописать в конец. Например, сохранить трассы и скриншоты упавших тестов:

```bash
python3 run_tests.py --headless --tracing retain-on-failure --screenshot only-on-failure
```

## Как прочитать результат

Нормальный итог полного запуска:

```text
7 passed, 2 xfailed
```

- `passed` — проверка успешно пройдена;
- `xfailed` — тест подтвердил уже известный дефект, это ожидаемый результат;
- `failed` — произошла неожиданная ошибка или обнаружен новый дефект;
- `XPASS(strict)` — известный дефект исправлен, но устаревшая отметка `xfail` ещё осталась в тесте.

Код возврата `0` означает успешный прогон. Подробности каждого известного дефекта находятся в `BUGS.md`.

## Ручной запуск для разработчика

Если автоматический скрипт использовать не нужно:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest --browser chromium
```

На Windows команда активации окружения: `.venv\Scripts\Activate.ps1`.

При падении assertion pytest выводит ожидаемый результат и фактические проблемные значения.

Важно: прямое открытие `/stats` на Netlify возвращает 404, поэтому тест корректно переходит туда через SPA-ссылку главной страницы.
