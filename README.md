# UI-тесты платформы модерации

Автотесты написаны на Python, pytest и Playwright. Они проверяют фильтры цены и категории, сортировку, «Только срочные», таймер статистики и переключение темы на мобильном экране.

Тест-кейсы находятся в `TESTCASES.md`, найденные дефекты — в `BUGS.md`, разбор задания по скриншоту — в `SCREENSHOT_BUGS.md`.

## Быстрый запуск на Mac

Понадобятся Python 3.10 или новее и интернет. Узнать версию Python:

```bash
python3 --version
```

Затем выполните ровно три действия:

1. Скачайте проект с GitHub и распакуйте ZIP.
2. Откройте терминал в папке проекта: в Finder нажмите папку правой кнопкой → **Службы → Новый терминал в папке**.
3. Запустите:

```bash
python3 run_tests.py
```

Скрипт сам создаст `.venv`, установит библиотеки и Chromium, после чего откроет браузер и запустит тесты. Команды `source .venv/bin/activate` вводить не нужно. Поэтому запуск одинаково работает в стандартном терминале Mac, Zsh, Bash и Fish.

Если пункта **Новый терминал в папке** нет, откройте приложение «Терминал», напишите `cd ` с пробелом, перетащите папку проекта в окно терминала и нажмите Enter. После этого выполните `python3 run_tests.py`.

Важно: не переносите `.venv` с другого компьютера. Если она была скопирована вместе с проектом, удалите только папку `.venv` внутри проекта и снова выполните `python3 run_tests.py`.

## Одинаковый запуск на Mac и Windows через Docker

Этот способ не требует установки Python и создаёт одинаковое окружение на обеих системах. Понадобится только [Docker Desktop](https://www.docker.com/products/docker-desktop/). После установки запустите Docker Desktop и дождитесь, когда он будет готов.

Дальше нужны три действия:

1. Скачайте проект с GitHub и распакуйте ZIP.
2. Откройте терминал в папке проекта:
   - Mac: Finder → правая кнопка по папке → **Службы → Новый терминал в папке**;
   - Windows: откройте папку в Проводнике, введите `powershell` в адресной строке и нажмите Enter.
3. Выполните одну и ту же команду на Mac и Windows:

```text
docker compose run --rm tests
```

При первом запуске Docker скачает образ браузера и соберёт контейнер, поэтому потребуется несколько минут. Следующие запуски будут быстрее. Браузер работает внутри контейнера без видимого окна, а результат выводится в терминале.

Если тесты или зависимости изменились, пересоберите контейнер:

```text
docker compose build --no-cache
docker compose run --rm tests
```

Запустить только desktop-тесты:

```text
docker compose run --rm tests python -m pytest -m desktop --browser chromium
```

Только mobile-тесты:

```text
docker compose run --rm tests python -m pytest -m mobile --browser chromium
```

## Дополнительные варианты запуска на Mac без Docker

Без видимого окна браузера:

```bash
python3 run_tests.py --headless
```

Запустить только отдельную группу:

```bash
python3 run_tests.py --desktop
python3 run_tests.py --mobile
```

Переустановить зависимости и Chromium:

```bash
python3 run_tests.py --setup
```

Сохранить трассы и скриншоты упавших тестов:

```bash
python3 run_tests.py --headless --tracing retain-on-failure --screenshot only-on-failure
```

## Как понять результат

Нормальный итог полного запуска:

```text
7 passed, 2 xfailed
```

- `passed` — проверка успешно пройдена;
- `xfailed` — тест подтвердил уже известный дефект, это ожидаемый результат;
- `failed` — неожиданная ошибка или новый дефект;
- `XPASS(strict)` — известный дефект исправлен, но отметка `xfail` ещё не удалена из теста.

Код возврата `0` означает успешный прогон. Подробности известных дефектов находятся в `BUGS.md`.

Важно: прямое открытие `/stats` на Netlify возвращает 404, поэтому тест переходит на страницу статистики через ссылку главной страницы.
